02 / RUNTIME BOUNDARY

One engine behind the command line, the desktop and the browser.

rspice-core parses SPICE netlists, evaluates devices, assembles modified-nodal-analysis systems and runs the analyses. The command line and the desktop and browser application run the same rspice-core code, so a result does not depend on how the run was launched. Where a deck needs physics RSpice does not have, it stops with an error naming the parameter or model level responsible rather than approximating.

DESKTOP

egui / wgpu

The native application: eight workspaces covering projects, schematic and symbol design, simulation setup, results, verification, models, netlists and scripts, and stimulus definitions.

BROWSER

WebAssembly

The same application in a browser tab, with simulations in a worker off the page's main thread. Experimental: it needs WebGPU, and phones and tablets are not a qualified target.

AUTOMATION

Command line

rspice runs decks and studies, checks and inspects them, converts result files and compares them with golden results. Its exit status is the verification contract.

03 / SOURCE BUILD

Build the command line or the application from a checkout.

Signed installers are not published yet. The toolchain is pinned to Rust 1.94 by the repository's rust-toolchain.toml, which rustup picks up on its own.

Add --features generated-veriloga-catalog to compile in the 43 compact models generated from their Verilog-A sources. At the workspace root a plain cargo build builds the command line and the application; use -p <package> for a tool or --workspace for everything. Use the repository README and CI configuration for the checked-out revision.

05 / INTERFACES

Interface scope.

  • Command line: rspice run, study, check, info, models, compare, convert, health, capabilities, compile-va and completions. Runs write SPICE raw, ASCII raw, CSV, TSV, JSON, HDF5 or VCD, and can emit JUnit or TAP reports and a versioned JSON run summary. The full manual is crates/rspice-cli/README.md in the source.
  • Desktop application: rspice-app, built with egui and wgpu, with local file access. The guides above describe it.
  • Browser: the same application compiled to WebAssembly. It is experimental, needs a WebGPU-capable browser, and keeps projects in the browser's storage.
  • Python: Tools › Scripts runs Python workflows inside the application, on a Python runtime RSpice manages rather than a system interpreter. The current source has no separate Python or JavaScript binding package.
  • Verilog-AMS: one compiler for .va and .vams sources. In the application a module is a cell view; rspice compile-va compiles one on its own.

06 / VALIDATION DISCIPLINE

Validation targets in the source tree.

The workspace contains unit tests per crate, integration suites, oracle-replay fixtures for history-coupled device behavior, and corpus harnesses: ngspice and Xyce alongside GF180MCU, ISCAS85, mixed-signal and paranoia suites. Each ngspice deck runs in a watchdog-supervised process and is compared row by row with ngspice output; the Xyce harness reports unsupported Xyce contracts instead of omitting the deck.

The validation methodology describes comparison inputs, failure states, and tolerance requirements. The generated validation page publishes source-controlled gate configuration, corpus inventories, benchmark context, and any exact-revision CI artifact available to the site build.
