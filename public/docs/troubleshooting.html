01 / PROBLEMS AND CONSOLE

Two lists, two questions.

View › Problems lists the conditions that stand against the design now: check findings, run refusals, compile errors. A finding leaves the list when the design stops causing it; one whose inputs have changed since it was found is shown faint as stale rather than dropped. A finding that knows where it is takes you there when you click it.

View › Console (Ctrl+J; Ctrl+Alt+J in the browser) is the session's record of what happened, in order, and keeps entries after they stop being true.

02 / A REFUSED RUN

Refused before any solving, with the reason.

Every run is checked first, and the engine builds every deck it would run before solving any of them. Whatever it refuses blocks the run, and the reason, naming the analysis, the instance and what is wrong, is listed in Problems. Simulate › Check and netlist runs the same checks without starting a run.

  • A deck that needs physics RSpice does not have stops with an error naming the parameter or model level responsible; RSpice does not approximate around it.
  • An output expression that names a node the design does not have is flagged on Simulate › Setup › Outputs & expressions.
  • A specification whose measurement no analysis produces is flagged on Requirements & specifications.
  • Design problems found by Design › Check cellview (Ctrl+E) or Check design are listed with the rest; see Schematic entry.

03 / CONVERGENCE

When the solve does not converge.

The engine's Newton solver has four aids for hard circuits: gmin stepping, source stepping, pseudo-transient continuation and arc-length continuation. Simulate › Setup › Simulator options sets what counts as converged, how the solve recovers when it does not, how many iterations each stage gets, how time advances, and how the matrix is factored. Its values reach the engine through the deck's .OPTIONS block.

04 / RECOVER INTERRUPTED WORK

Checkpoints, compared before anything is replaced.

If a session ends with work unsaved, the start screen shows an Interrupted session card; choose Review…. The same checkpoints are on the Recovery page of the project launcher (File › Open recent › All projects…, Ctrl+Shift+O), and the Project workspace has a Recovery page for the open project.

  • Each checkpoint states where it came from, when it was captured and what it does not include.
  • Open recovery comparison opens a comparison copy; recovery never overwrites the saved project. A checkpoint that fails its integrity check cannot be opened this way.
  • Discard selected checkpoint… deletes only that checkpoint; the saved source is not modified.

05 / SAFE MODE

Start with less, to find what is wrong.

The project launcher's Safe mode page turns features off for this launch of RSpice only. Choose any of:

OPTIONEFFECT
Disable third-party extensionsBuilt-in signed components remain available.
Do not reopen prior documentsStart in the empty workbench with project files closed.
Reset dock and monitor geometryRecover panels and windows to the primary display.
Open project read-onlyPrevent working-document writes while you diagnose content.
Disable GPU accelerationListed, but this build cannot switch to a software renderer after start-up, so it cannot be chosen.

Then choose Start RSpice in safe mode. Safe mode lasts until RSpice restarts; the session from before it is kept for the next normal launch.

06 / LOST PANELS AND WINDOWS

Put the workbench back.

Window › Layout › Reset layout returns the side docks to their default widths and collapses the console. View › Focus mode (Ctrl+Shift+F) hides the console and the side docks; the same key brings them back. On the desktop, Window › Recover off-screen windows… brings the application windows you select back onto the screen, and Merge all windows… gathers detached windows back into one.

07 / THE BROWSER BUILD

Experimental, and it needs WebGPU.

The browser build draws with WebGPU, so it needs a browser that supports it. Phones and tablets are not a qualified target. Some keys differ from the desktop because the browser keeps them: Keyboard shortcuts lists both. Projects saved in the browser are kept in that browser's storage.

08 / REPORT A PROBLEM

Help › Report a problem…

The dialog shows what support needs to reproduce a problem: the RSpice version, the platform, the graphics adapter, the file the session log is written to, and the address to write to, hello@rspice.app.

  1. Choose whether to include the session log. Your home folder is removed from it.
  2. Tick I reviewed what the bundle contains, then Create support bundle… and choose where to save it.
  3. Send the bundle with a description of what happened.

A support bundle is made only when you create one, and it is saved where you choose: you send it yourself. Project content, models, results, credentials, license keys and recovery checkpoints are excluded. Help › About RSpice has Copy diagnostics, which copies the version and platform details to the clipboard. Report a security issue through the security policy instead.
