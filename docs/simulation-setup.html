01 / THE SIMULATION PLAN

A plan is the ordered list of what to compute.

Each project has an active simulation plan: its analyses in order, with the variables, outputs, specifications, run set, model choices, solver options and save policy that go with them. The Simulate workspace (Alt+3) edits the active plan, one setup page at a time.

Simulate › Manage simulation plans… keeps several plans in one project: create, activate, rename, clone, compare, archive and restore them, export one as a package or import one, and queue a campaign over several. Archiving a plan never changes the results already recorded against it.

02 / ANALYSES

The analyses the application offers.

Simulate › Add analysis… opens the Add analysis or workflow catalogue. It lists every analysis below, grouped as here and searchable by name or code, and each row says how it stands against the current plan, for example that an instance is already in it. Choosing a row adds an instance to the plan; a plan can hold more than one instance of a kind.

PREVIEWThe catalogue marks the analyses tagged above as a preview engine, non-sign-off. They produce real results and are never hidden, but those results are stamped so they cannot be carried into a sign-off package as production results.

03 / SETUP PAGES

One page per concern of the plan.

Simulate › Setup opens each page of the Simulate workspace.

PAGEWHAT IT HOLDS
AnalysesThe plan's analyses, in order.
ExcitationsEvery source and RF port that drives the circuit, across the whole hierarchy, and which analyses read each. Sources are edited on the schematic; a row takes you to its instance.
Design variablesThe typed parameters the plan resolves.
Outputs & expressionsThe expressions a run saves, each with whether it resolves against the design, so a name the design lacks is caught before a run.
Requirements & specificationsThe limits results are judged against, and any limit whose measurement no analysis produces.
PVT, sweeps & variationThe run space: process, voltage and temperature axes, sweeps and variation, and the number of runs they multiply out to.
Models & sectionsThe loaded model libraries, the corner section a run will use from each, and whether each source is pinned well enough to reproduce.
Simulator optionsConvergence tolerances, how the solve recovers when it does not converge, iteration limits, timestep control, matrix factoring and model temperature, written into the deck's .OPTIONS.
Save, streaming & retention policyWhat a run keeps, how results arrive while it runs, and what that costs.

Setup › Configuration sets… opens the project's configuration page, the hierarchy editor that decides which view each instance netlists with.

04 / STIMULUS LIBRARY

Reusable source definitions.

The Stimulus library workspace (Alt+8, or Simulate › Setup › Stimulus library) holds the project's stimulus definitions: a waveform written once and used by many sources. A definition is written there or saved from a placed source's properties. The library plots the waveform with the engine's own evaluator and shows the SPICE card it produces, and it can place a source that carries the definition's saved revision. When placed sources use an older revision of a definition, the library says how many.

05 / CHECK AND RUN

Nothing runs that would be refused.

  • Simulate › Check and netlist runs the checks a run would, then has the engine build every deck the run would dispatch, without solving. What it finds is listed in View › Problems.
  • Simulate › Run (F5; Ctrl+Enter in the browser) runs the plan. It is checked first: an analysis that cannot run on this circuit is refused before any solving, naming the analysis, the instance and the reason. Stop (Shift+F5; Ctrl+Shift+Enter in the browser) ends the run.
  • Open generated netlist (Ctrl+L; Ctrl+Alt+L in the browser) shows the SPICE deck the design produces, read-only and mapped back to the schematic, in the Netlist and script editor.
  • Run history… lists the running and retained runs with their manifests.

A finished run's data opens in the Results workspace. When a run is refused, Troubleshooting explains where to look.

06 / PROBES AND ANNOTATION

Mark signals on the schematic, and read values back onto it.

  • Simulate › Probe (P) places a voltage or current probe flag on the schematic; the flag records the output it measures.
  • Annotate DC operating point shows or hides the DC operating point on the schematic, and Operating-point table lists it.
  • Annotate transient voltages shows or hides the transient's node voltages at results cursor A on the schematic.
